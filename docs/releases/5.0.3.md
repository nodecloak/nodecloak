# NodeCloak 5.0.3

- Windows 应用代理增加断线保护：节点不可用或代理程序异常退出时，指定应用无法直连；主动停止应用代理后恢复普通网络。
- Windows 的 Claude Code CLI、Codex CLI 和 VS Code Claude 扩展沿用对应应用的代理节点，兼容原生、npm／pnpm 安装及手动选择程序路径的已有配置。
- 新增 WSL 接入入口。接入 Ubuntu 并开启应用代理后，重新打开 Codex、Claude 和 VS Code Claude 会话即可使用对应节点；代理故障时保持断网。
- 改善 WSL 接入重试、配置恢复、程序更新和 Ctrl+C 取消操作的兼容性，保留已有节点和前置代理配置。

WSL 接入需要 Python 3、iproute2、util-linux 和可用的用户网络隔离；受保护会话不支持 Windows 程序互操作及任意宿主机 TCP 回环服务。首次接入或切换保护状态后，请重新打开终端和扩展会话。Linux 桌面版应用代理仍不可用。

## English

- Windows application proxy now blocks direct connections for assigned applications if a node or proxy process fails. Explicitly stopping application proxy restores normal networking.
- Native Claude Code CLI, Codex CLI and the VS Code Claude extension on Windows share their corresponding application nodes, including npm/pnpm installations and existing manually selected executable paths.
- Connect Ubuntu from the WSL section, enable application proxy and reopen Codex, Claude or VS Code Claude sessions to use their assigned nodes. Protected sessions remain disconnected when the proxy fails.
- Improved WSL integration retries, configuration restoration, adapter updates and Ctrl+C handling while preserving existing nodes and first-hop proxy settings.

WSL integration requires Python 3, iproute2, util-linux and working user network isolation. Protected sessions cannot invoke Windows programs or access arbitrary host TCP loopback services. Reopen terminals and extension sessions after integration or protection changes. Application proxy remains unavailable in the Linux desktop app.
