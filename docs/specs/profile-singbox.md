# Profile-scoped node proxy

The application embeds the pinned sing-box 1.14.4 executable separately from its own Rust networking code. The browser keeps using its existing profile HTTP relay. For VLESS/VMess, an authenticated internal loopback HTTP inbound forwards through the selected node. `preProxy` becomes that node's `detour`, so the wire order is browser → local relay/core → first-hop proxy → remote node → destination. The first-hop CONNECT/SOCKS request names the remote node endpoint. The node UUID is used only by the node protocol, never reused as first-hop authentication. A VLESS link without TLS still uses the protocol's plaintext transport. Existing HTTP/HTTPS/SOCKS5 and API extraction retain their prior implementation.

Only typed VLESS and VMess options are accepted. The initial import supports TCP, WebSocket, HTTPUpgrade and gRPC, TLS and VLESS Reality/Vision. XHTTP, arbitrary JSON, subscriptions and unsupported link fields are rejected. No TUN, system proxy/DNS mutation, global core API, configuration include or downloaded rule set is accepted. The existing system resolver may resolve a node or first-hop hostname; it is not reconfigured. A separate application's TUN/transparent routing can still affect outbound sockets; this application cannot guarantee bypassing OS routing.

UUIDs use the existing profile credential store. Persistent public node options contain TLS/transport settings only. Portable encrypted documents use schema 6 for nodes; older clients reject the document rather than changing its route. Profiles should be copied/edited/reset using existing credential reference ownership rules. Node import does not grant MCP permissions or accept arbitrary core configuration.

The core receives generated JSON over anonymous pipes; no credentials appear in command-line arguments or configuration files. Each running profile/probe owns a helper and core. A held parent pipe implements lifetime coupling; its EOF terminates only that core. Windows additionally uses a kill-on-close Job Object. Temporary directories contain only a hash-checked executable, not node configuration. The listener is always IPv4 loopback and receives random per-instance HTTP credentials. Readiness comes from the owned helper after its own core confirms the exact inbound bound and startup completed. A supplemental authentication check uses a locally rejected health domain without dialing a user node. Verified-executable preparation has a30-second budget per attempt; listener startup has a separate5-second budget, with a35-second attempt cap. Ownership is monitored during streamed extraction so cancellation prevents a late spawn. Port contention is retried at most three times. Core failure never becomes a direct browser connection.

Release preparation pins archive hashes for Windows x64 and macOS Intel/Apple Silicon. The upstream GPL license, exact source archive and provenance accompany release notices; upstream code is not relicensed as MIT. The NodeCloak product name is distinct from the upstream project name. macOS release builds must validate the executable delivered within the final application as well as the core's launch/configuration path.
