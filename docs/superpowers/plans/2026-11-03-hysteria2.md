# Hysteria2 Implementation Plan

> Execute inline with test-first checks; retain the existing per-profile core lifecycle.

**Goal:** Import `hysteria2://` and `hy2://` links and use their credentials, SNI and explicit insecure TLS flag in browser profile proxies.

**Architecture:** Extend the existing typed node configuration and private helper allowlist. Keep the full userpass value in the existing credential store, never in public node options. QUIC requires a UDP-capable first hop, so reject HTTP/HTTPS chaining and support SOCKS5 UDP.

**Tech Stack:** Rust, sing-box 1.14.4, TypeScript, React, Vitest.

**Spec:** Existing `docs/specs/profile-singbox.md` plus Hysteria2 URI and sing-box outbound specifications.

## Constraints

- Loopback only; no TUN or system proxy/DNS changes.
- Preserve case and percent decoding of opaque auth, including `username:password`.
- Accept single-port links, optional SNI and `insecure=0/1`; reject unsupported options rather than ignore them.
- No live credentials in tests, documentation or diagnostics.
- Keep all existing VLESS/VMess and ordinary proxy behavior.

## Tasks

1. Add failing TypeScript parser/draft tests for aliases, userpass, default 443, IPv6, invalid options and incompatible first hops. Add Rust tests for generated HY2 output, TLS policy, credentials and helper validation.
2. Extend `src/proxy-node.ts`, `src/browser-profiles.ts`, `src-tauri/src/proxy.rs`, `src-tauri/src/proxy/node.rs` and `src-tauri/src/proxy/core.rs`. Generate HY2 `password`, never `uuid`, and reconstruct that same shape at the helper boundary.
3. Update the existing proxy editor and translations; show Hysteria2, opaque auth, TLS verification state and UDP chaining requirements. Add a component import test.
4. Run frontend tests/build, Rust tests and a real local sing-box HY2 server/client transfer with synthetic credentials and a local certificate. Validate wrong auth/certificate failures and clean up owned fixtures. Update the feature spec with scope and evidence.
