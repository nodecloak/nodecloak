## Pre-release compatibility gate

The unpublished first candidate `ad95e3b74213ea3deeacc83bdf31adac6c478a2d` failed one Apple Silicon normal-Firefox-quit check in run `41574085346`. The same strict diagnostic fixture passed on both architectures in run `41574989112`; all observed AppKit dispatches there succeeded, so the exact cause of the earlier intermittent timeout is not established by those traces.

Inspection exposed a separate provable gap: an unregistered AppKit lookup silently discarded the sole quit request. A deterministic regression fails on one-shot behavior and passes with discovery/undelivered-request retry within the original eight-second budget. Accepted requests are never repeated; a mutation test verifies that guarantee across multiple polling rounds. Normal close never escalates to force termination. Preserve cookie-persistence assertions and require the unchanged native gate on the final release source. No packages from a failed candidate may be published.

The second unpublished candidate `8c6b4670ddf01b92a9ae122e26547699b0a2d9ee` passed the Apple Silicon release job, but Windows run `41576589011` failed the Firefox large-session export shutdown gate. The unchanged native fixture passed locally before the fix, so that CI timeout is intermittent. Investigation and Mozilla's remote server shutdown implementation identified a concrete retained-WebSocket cleanup gap. A loopback regression fails on the old code and passes when quit acknowledgements are bounded and the owned transport is released before the unchanged process/PID/profile-lock checks. The original fifteen-second shutdown budget, staged commit ordering, full-data equality and existing-profile sentinel checks remain mandatory. Evidence is retained privately in `.qa/release-4.0.0/`; no failed candidate assets may be published.
